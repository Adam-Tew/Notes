
# Vulnerabilities in password-based login
#### Username enumeration via different responses
When enumerating usernames/password, look for a change in:
* Content length
* Status
* Response time
Mix in valid usernames/password to use these as a basis.
* If you're enumerating usernames try having an empty password field or a super long one.
#### Username enumeration via subtly different
Check for a difference in error messages, could be something difficult to see like an extra space in the text. Copy it and grep the text in **intruder** and see if there's a change between valid and invalid usernames/password.
# Flawed brute-force protection
#### Broken brute-force protection, IP block
If I.P get's blocked after three wrong attempts try sending a valid username/password after 2 attempts. By using a valid login in-between the attempts it could reset the "wrong attempts" counter on the I.P. Allowing for unlimited tries.
#### Username enumeration via account lock
If valid accounts gets locked after X amount of wrong tries but invalid accounts doesn't then this can be used to differentiate valid from invalid usernames. 

#### Broken brute-force protection, multiple credentials per request
If you can submit credentials in JSON format. Try replacing the single string value with an array of strings containing all of the potential passwords. For example:
```
"username" : "carlos",
"password" : [
    "123456",
    "password",
    "qwerty"
    ...
]
```
