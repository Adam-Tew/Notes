# Failing to handle unconventional input
#### High-level logic vulnerability
* If you have something in cart, intercept and try adding a value and see if cart gets updated. Then try a negative value so you will get negative items in cart and the price might be in a negative value itself.
#### Low-level logic flaw
* And a high quantity of items in your cart, if the price exceed the maximum value permitted for an integer (2 147 483 647) then the price could loop back starting at negative -2 147 483 647.
#### Inconsistent handling of exceptional input
* If there's a company email which gives you admin and you can register an email. Try registering a super long email and see if your own email gets cuts out at the end but that you still get the email despite this.
	* `very-long-string@dontwannacry.com.YOUR-EMAIL-ID.web-security-academy.net`
	* Only very-long-string@dontwanancry.com should be left.
# Making flawed assumptions about user behavior
### Trusted users won't always remain trustworthy
#### Inconsistent security controls
* If there's a company email and you can change your own email, try changing to the company email.
### Users won't always supply mandatory input
#### Weak isolation on dual-use endpoint
* If you intercept the request to change your password. Try changing the username to someone else's and removing the "current password" parameter and see if it works.
#### Password reset broken logic
* When you click "Forgotten password" and you get a link with a token. Click on the link and see if you can change your password even when removing the token. If so get a new link, try changing the username parameter to someone else's, remove the token and change the password.
### Users won't always follow the intended sequence
#### 2FA simple bypass
If the regular login flow is:
1. Enter username and password
2. Enter 2FA code
3. Get redirected to /my-account
Try:
	1. Enter victim's username and password
	2. Send request to /my-account directly.
#### Insufficient workflow validation
If the regular buying flow is:
1. Add item to cart
2. Click buy
3. See that a order-confirmation is being sent.
Try:
	1. Add item to cart
	2. Manually send the order-confirmation.
#### Authentication bypass via flawed state machine
If the regular login flow is:
1. Enter username and password
2. A second role selector request is being sent in the background
3. Get logged in as a regular user
Try:
	1. Enter username and password
	2. Intercept and drop the second role selector request.
